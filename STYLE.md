# Стиль кода

Канон XFCE (GNOME style guide, на котором он построен). Правила обязательны для
всего в `terminal/`, `tests/*.c` и для новых файлов; в чужом коде, который мы не
трогаем, оставляем как есть, чтобы дифф с апстримом оставался читаемым.

## Лицензия и атрибуция

- Лицензия проекта — GPL-2.0-or-later, текст в корне (`COPYING`); в
  `meson.build` она же в SPDX-виде.
- Каждый файл исходников начинается с такой же GPL-шапки, как в апстриме:
  `/*-`, `Copyright (c) <год> <автор>`, текст GPL-2+ и ссылка на лицензию.
- Проект пишется с нуля: чужой код не копируем. Берём идеи и публичные знания.
- Упоминать другие проекты в коде, комментариях и документах не нужно, если
  лицензия этого не требует. Там, где нельзя иначе: заимствованный код с его
  указанием авторства и обязательные уведомления GPL.

## Формат

- Отступ — 2 пробела. Табов в файлах нет.
- `{` на той же строке, что и сигнатура или условие.
- Пробелы вокруг бинарных операторов, присваиваний и после запятых; перед `;`
  пробела нет.
- Максимальная длина строки — 100 знаков; длинные строки переносим по
  аргументам, один аргумент в строке, как в апстримных файлах.
- Пустая строка — одна, без пробелов; в конце файла перевод строки есть,
  висячих пробелов нет.

## Порядок в файле

1. Шапка с лицензией (если файл новый).
2. `#ifdef HAVE_CONFIG_H` / `#include <config.h>`, если файл это использует.
3. Включения: сначала системные (POSIX, libc), потом GTK/GLib, потом заголовки
   проекта; заголовок самого файла — последним. Внутри группы — по алфавиту,
   как в апстримных файлах.
4. Макросы, `G_DECLARE_FINAL_TYPE`/`G_DEFINE_TYPE`, перечисления, структуры.
5. Статические прототипы функций — одним блоком, перед определениями.
6. Определения функций — в том же порядке, что и прототипы.

## Структуры и поля

- Сначала публичные поля (то, что в заголовке), потом приватные; флаги
  `guint x : 1;` — в конце, отдельной строкой.
- Поле, которое меняет таймер или источник, снимается в `finalize`; поле,
  принадлежащее виджету, снимается вместе с ним.

## Функции

- Имена — `snake_case` в стиле проекта (`terminal_window_*`, `gtk_*`), типы —
  `CamelCase`, макросы и элементы перечислений — `UPPER_SNAKE`.
- Значения глобальных констант и параметров GObject — через `G_PARAM_STATIC_STRINGS`.
- Возвращаемое значение — `gboolean` для «удалось/не удалось», `NULL` для
  «объекта нет»; ошибки — через `GError **`, а не через возврат кода.
- Публичный API получает gtk-doc-комментарий:
  ```c
  /**
   * terminal_window_apply_title:
   * @window: the window whose title changes
   *
   * Sets the window title from the active pane.
   **/
  ```
- Статические и внутренние функции — обычный комментарий `/* … */`, без
  gtk-doc-разметки.
- Функция делает одну вещь; если в теле цикл с несколькими ветками, тело
  разбивается на функции, а не на комментарии «шаг 1, шаг 2».

## Проверки

- На входе публичной функции — `g_return_if_fail` / `g_return_val_if_fail`.
- `NULL` из `g_object_get` не игнорируем: либо проверяем, либо снимаем сразу
  `g_free`.
- Ошибка не проходит молча: либо обрабатывается, либо возвращается.
- Успех — `return TRUE;`, неудача — `return FALSE;` (не «1» и не «0»).

## Комментарии и язык

- Код и комментарии в коде — по-английски: так их читает и правит команда XFCE,
  и по ним приходят патчи в апстрим.
- Кириллицы в `.c` и `.h` нет (проверяется `tests/style-check.sh`).
- Комментарий объясняет **почему**, а не пересказывает код. Ссылки на апстрим
  (`upstream:`, `GNOME:`) — коротко, одной строкой.
- Документация для пользователя (`FORK.md`, `CONTEXT.md`, `AGENTS.md`) и тексты
  интерфейса — по-русски.

## Переводы

- Любая новая строка интерфейса — через `_()` и сразу попадает в `po/*.pot`
  (`ninja -C build xfce4-terminal-pot`), перевод — в `po/ru.po`.
- Строка без перевода в `ru.po` не остаётся: `msgattrib --untranslated
  po/ru.po` должен показывать только `HTML`.

## Тесты

- Стенды на bash, проверки — с сообщением о том, что именно не так, а не
  «FAIL»: `stand_check no "панель скрылась" "окно всё ещё видно"`.
- Проверки ищут элементы по обоим вариантам названия (английский и русский):
  интерфейс в стенде русский, но при отвалившемся переводе появится оригинал.
- Каждый стенд сам гасит свои настройки в конце: иначе они влияют на
  следующие прогоны.
